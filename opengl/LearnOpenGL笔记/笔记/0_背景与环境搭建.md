# OpenGL 基本背景

OpenGL 只是一个规范（Specification），主要对 API 进行要求，由 Khronos Group 维护，实现 OpenGL 库的通常是图形卡厂商。

OpenGL 3.2 以前采用的是 *Immediate Mode*（固定管线），易懂、易用，但是功能不够强大不够灵活，3.2 以后改用 *Core-profile*（可编程管线），更灵活和高效，但是更难入门。

OpenGL Extension：由驱动厂商提供的、尚未完全纳入标准的一些功能：
```cpp
if(GL_ARB_extension_name)
{
    // Do cool new and modern stuff supported by hardware
}
else
{
    // Extension not supported: do it the old way
}
```

OpenGL 的核心本质是一个*状态机*（由大量变量组合决定其行为），OpenGL 的状态就是 *OpenGL Context*，使用 OpenGL 就是在修改状态、使用状态，因此 OpenGL 函数分为两大类：
- State-changing function
- State-using function

尽管 OpenGL API 是 C 语言，其内部还是使用的 *Object* 作为数据和配置（状态）的容器，以下是假设、模拟的代码：
```cpp
// The State of OpenGL
struct OpenGL_Context {
  	...
  	object_name* object_Window_Target;
  	...  	
};
```

使用 OpenGL 的工作流往往类似以下代码：
```cpp
// create object
unsigned int objectId = 0;
glGenObject(1, &objectId);
// bind/assign object to context
glBindObject(GL_WINDOW_TARGET, objectId);
// set options of object currently bound to GL_WINDOW_TARGET
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_WIDTH,  800);
glSetObjectOption(GL_WINDOW_TARGET, GL_OPTION_WINDOW_HEIGHT, 600);
// set context target back to default
glBindObject(GL_WINDOW_TARGET, 0);
```

1. 通过 ID 区分对象
2. 将对象绑定到 Context 的某 Target
3. 设置 Target 的 options（选项/配置），从而修改此时绑定的对象的 options
4. 通过令 Target 解绑/绑定对象，使 Target 使用指定的“一套” options，比如 2 个对象使用不同的 3D 模型

# OpenGL 环境搭建

因为 OpenGL Context 的定义、GUI 窗口的实现、用户 IO 处理等功能都不在 OpenGL 标准内，并且不同平台实现不一样，因此需要一个跨平台的辅助工具帮助完成这些基本工作，比如 GLFW 库。

除了 Context、窗口、IO，还有一个功能是非标准的，即 *加载/定位 OpenGL 函数的具体实现地址*，具体实现一般位于显卡驱动内，需要类似以下的代码流程来实现函数代码定位：
```cpp
// define the function's prototype
typedef void (*GL_GENBUFFERS) (GLsizei, GLuint*);
// find the function and assign it to a function pointer on Windows
GL_GENBUFFERS glGenBuffers  = (GL_GENBUFFERS)wglGetProcAddress("glGenBuffers");
// function can now be called as normal
unsigned int buffer;
glGenBuffers(1, &buffer);
```

辅助完成此功能的工具是 GLAD，GLAD 比较特殊的地方在于它仅提供 `glad.h` 和 `glad.c` 两个文件，将这两个文件加入到项目中即可使用其功能。

> 注意！实际负责查找 OpenGL 函数地址的工具是 `glfwGetProcAddress()`，类似 `wglGetProcAddress()`，但是跨平台。GLAD 的 `gladLoadGLLoader()` 只负责 *名字映射*，比如 GLAD 定义一个全局函数指针 `glClearColor`，该函数指针指向真正的 `glClearColor` 实现。

使用 GLAD + GLFW 时，需注意先包含 `glad.h` 再包含 `glfw3.h`：
```cpp
#include <glad/glad.h>
#include <GLFW/glfw3.h>
```

> 系统自带的 opengl32.lib（windows）、libGL.so（linux）只提供了基本的 OpenGL 1.1 版本功能，可以说基本上是无用的，实际的 OpenGL 实现都在显卡驱动里，需要借助 GLAD 或其它工具动态的加载和定位。
