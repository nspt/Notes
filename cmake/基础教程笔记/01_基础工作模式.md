# 1. 基础工作模式

## CMake 核心工作模式

1. 创建 Target（本质上就是一堆属性的集合）
2. 设置/修改 Target 属性

## CML（CMakeLists.txt）关键指令：

### `cmake_minimum_required(VERSION <number>)`

指定 CMake 的工作版本，必须指令

### `project(<name> VERSION <number>)`

无需关心具体细节，理解为制定项目名和版本号（版本号会用于安装、依赖判定等场景）即可，几乎是顶层 CML 必须指令

### 创建 Target

1. `add_executable(<name>)`

    添加一个可执行目标

2. `add_library(<name> [TYPE])`

    添加一个库目标，`TYPE` 可以是 `STATIC`/`SHARED`……，但是不建议主动指定，建议由调用者通过 `BUILD_SHARED_LIBS` （True/False）来指定

### 设置 Target

1. `target_sources()`

    设置 Target 的源文件、头文件等相关属性，例：

    ```cmake
    target_sources(MyLib
        PRIVATE
            main.cpp
        PUBLIC
            FILE_SET MyLibHeaders
            TYPE HEADERS
            BASE_DIR MyLib
            FILES
                MyLib/MyLibHeader.h
    )
    ```

    头文件建议通过 `FILE_SET` 描述，`FILE_SET` 表示一个文件集合，其关键作用是将文件打包命名，为程序（主要是库）的安装提供支持，当安装库时，可以将库 Target 的 `FILE_SET` 安装到系统的包含目录，供其它程序使用。

    `FILE_SET` 的名字可以忽略，直接写 `FILE_SET HEADERS`，库安装时，会将 `FILES` 中的文件路径中的 `BASE_DIR` 移除，若 `BASE_DIR` 为当前目录，也可忽略。

2. `target_link_libraries()`

    设置 Target 间的依赖关系，如可执行文件依赖库，**不是单纯调用链接器，还包括 Target 属性的继承等其它依赖关系**，例：

    ```cmake
    target_link_libraries(MyProg
        PRIVATE
            MyLib
    )
    ```

3. Target 属性的作用域（Scope）

    Target 属性的作用域有三种，用于描述 Target 属性对依赖此 Target 的其它 Target 的可见性：

    - `PRIVATE`：仅此 Target 自己可见，如 Target 源文件
    - `INTERFACE`：仅依赖此 Target 的其它 Target 可见，如 Target 的对外头文件（自己不用的）
    - `PUBLIC`：`PRIVATE` + `INTERFACE`，如 Target 的头文件（自己用，也作为对外接口）

### 添加子目录

`add_subdirectory()` 会将子目录下的 CML **加入到全局配置**中，相对路径会进行自动转换，因为是加入到全局配置中，所以子目录中的 CML 可以引用尚未定义的、在其它子目录 CML 中定义的 Target。
